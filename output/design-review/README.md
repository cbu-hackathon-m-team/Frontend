# 화면 점검 기록

2026-10-31. 기존 로컬 개발 서버에서 확인. 실제 실행 결과가 아닌 명시된 화면 예시 사용.

1280px에서는 결과 카드 3개와 A/B 호출 경로를 함께 확인했다. 단일 입력 필드의 긴 값은 필드 내부에서 스크롤되며 페이지 너비를 늘리지 않는다. 데스크톱에서 테스트 선택, 단계→로그 전환, 변경 증거 탭, 결과 필터를 직접 조작했다. 모바일에서 사이드바→실행 목록→실행 상세, 예시 전환, 호출 선택을 확인했다.

검사: Vitest 33개 파일·185개 테스트 통과, 디자인 규칙 9개 통과, ESLint 통과, 타입 검사와 프로덕션 빌드 통과, `git diff --check` 통과. 빌드에는 기존 500kB 초과 청크 경고가 남는다. 일부 랜딩 차트 테스트에는 jsdom의 0 크기 컨테이너 경고가 있으며 테스트는 통과했다.

위 화면 예시 점검 이후 실제 백엔드 연동을 추가로 확인했다. 전용 임시 DB에서 브라우저로 등록·검사·설정 저장·승인·실행을 조작했고, 실제 Docker/uv/HTTP/WireMock 결과가 표시됐다. [회귀 실행](integrated-regression.png)은 HTTP 200과 재고 8이 유지되지만 배송 호출이 1 → 0이며, [동일 버전 대조군](integrated-control.png)은 4개 전체 통과다. 이력에서 과거 실행을 열었을 때 현재 목표 버전과 무관하게 당시 2.12.5 스냅샷을 유지했고, 새로고침과 `/validations/:id` 링크로 복원했다. [390px 실제 결과](integrated-mobile.png)의 문서 너비는 390px로 가로 넘침이 없었다. 서버 연결 시 실행 목록은 API의 여러 실행을 표시한다.

최종 커밋 대상 코드를 별도 checkout에서 검사했다. Vitest 35개 파일·193개 테스트, 디자인 규칙 9개, ESLint, 타입 검사·프로덕션 빌드가 통과했다. Windows checkout의 생성 파일 줄바꿈은 `pnpm typography:generate`로 갱신한 뒤 디자인 규칙을 검사했다. 기존 큰 번들 경고와 jsdom 차트 크기 경고가 남는다. 백엔드는 Ruff 검사·포맷과 33개 테스트를 통과했다.

GitHub 소스 전달은 로컬 샘플 대역이며 유료 AI·실제 메일 수신·GCP 권한은 확인하지 않았다. 스크린샷만으로 전체 접근성 준수를 보장하지 않는다.

## 공개 샘플 실행·기본값 점검

공개 `OSSGuard-Purchase-Demo`를 만든 뒤 실제 GitHub API 검사와 Git 복제부터 실행했다. 커밋 `e860635bdb292ca1c38a554b4f2c9b451ea20ac0`의 두 실행이 회귀 판정과 자원 정리를 완료했다. 첫 실행에서 발견한 Windows 읽기 전용 Git 객체 삭제 문제를 수정하고, 복구 후 다음 실행이 완료되는 것까지 확인했다. 이 후속 점검에서는 GitHub 소스 전달도 실제다.

[실행 설정 화면](prefilled-execution-setup.png)에서 실제 URL·패키지·목표 버전·포트·준비 확인 경로·자동 Mock 연결을 확인했다. 새 프로젝트는 이름·URL·브랜치가 채워지고, 업무 규칙과 4개 테스트도 불러온다. 이메일 수신 주소는 선택 사항이다. 제목과 같은 판정 배지, 등록 폼과 겹치는 빈 상태 안내를 정리하고 준비 상태에 맞춰 다음 행동을 안내한다. 비교·필터·로그 조사 기능은 유지했다.

후속 검사: 대시보드·검증 관련 53개 테스트 통과, 연결 폼 최종 조정 후 관련 8개 재검사 통과. `@shadcn/lint` 6개 규칙이 켜진 ESLint와 디자인 규칙 9개 통과, 예외 추가 없음(`eslint-suppressions.json`은 빈 객체). 백엔드 단위 26개·통합 9개와 Ruff 검사·포맷 통과. 유료 AI·실제 이메일·GCP 배포는 후속 확인 범위다.
